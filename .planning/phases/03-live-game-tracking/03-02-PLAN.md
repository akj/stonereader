<objective>
Fix WR-02 — replace the `_friendly_player_id = 1` constant stub at `stonereader/services/_engine.py:85` with a real resolution algorithm derived from `hslog.export.FriendlyPlayerExporter`. Implement the two-path heuristic (AI fast-path at CREATE_GAME + SHOW_ENTITY-into-HAND fallback) inline in the engine — no hslog import (keeps the engine reusable for Phase 4 replays per Phase 2 D-10).

This requires a small breaking change to `CreateGamePacket.players`: today the parser emits a 4-tuple `(entity, name, hi, lo)` (entity doubles as player_id), but the AI heuristic needs `player_id` distinctly. We update `CreateGamePacket.players` to a 5-tuple `(entity_id, player_id, name, hi, lo)`, update the parser to retain `player_id` from `hslog.packets.Player`, update the engine's destructure at `_engine.py:175`, and carry the existing test callsites forward.

Purpose: Without this fix, LIVE-02 / LIVE-03 / LIVE-04 are inverted in ~50% of games (the half where the local player is assigned CONTROLLER=2 by the server coin-flip). Phase 3 cannot ship correctly without it.

**Review feedback addressed (from 03-REVIEWS.md HIGH #2):**
- **Re-bucketing approach changed** — the original "swap accumulated lists" approach assumed all pre-resolution rows were uniformly inverted. That's wrong if mixed timing produces correctly-attributed AND incorrectly-attributed rows in the same accumulators. Replaced with `_rebucket_from_entities()` which discards the accumulators and rebuilds from authoritative `_entities` CONTROLLER tags using the new `_friendly_player_id`.
- **Mixed-timing test added** — `test_mixed_timing_fallback` validates that events fired before AND after fallback resolution are both correctly attributed in the final state.
- **CreateGamePacket consumer audit completed** — all 4 source consumers identified: `_engine.py:175` (destructure), `_parser.py:145` (emit), `test_engine.py:25/56`, `test_parser.py:31`, `test_exceptions_packets.py:81-92` (default-shape — tested with `players=()` so no breakage). All listed in `read_first` and updated in this plan.
- **Reconnect-specific test added** — `test_reconnect_resolves_friendly` covers second CREATE_GAME re-resolution.
- **Buffering rejected, authoritative recompute chosen** — buffering controller-dependent bucketing until friendly-player resolution would require deferring all CardDrawn/CardPlayed event emission, which contradicts the Phase 2 contract that subscribers receive events synchronously. Authoritative recompute keeps the existing event flow but ensures the published GameState `player_drawn`/`opponent_drawn` reflect the resolved friendly_player_id by recomputing from `_entities`.

Output: Updated packets / parser / engine + 6 passing tests + 3 carry-forward test updates.

    ```python
    def _resolve_friendly_player_ai_heuristic(
        self, players: tuple
    ) -> None:
        """WR-02 fast-path. Mirrors hslog.export.FriendlyPlayerExporter logic.

        If exactly one player has lo == 0 (AI account) and one has lo != 0
        (real account), the real account is friendly. Resolves immediately
        on CREATE_GAME consumption.
        """
        ai_pids: List[int] = []
        real_pids: List[int] = []
        for _entity_id, player_id, _name, _hi, lo in players:
            if lo == 0:
                ai_pids.append(player_id)
            else:
                real_pids.append(player_id)
        if len(ai_pids) == 1 and len(real_pids) == 1:
            new_friendly = real_pids[0]
            if new_friendly != self._friendly_player_id:
                self._friendly_player_id = new_friendly
                self._rebucket_from_entities()
            self._friendly_player_resolved = True

        self, p: ShowEntityPacket

        Per FriendlyPlayerExporter: in multiplayer games (both players have
        lo != 0), watch CONTROLLER tags during FULL_ENTITY/SHOW_ENTITY. The
        first SHOW_ENTITY whose target zone is HAND is the friendly player's

        new_zone = p.tags.get("ZONE")
        if new_zone != int(Zone.HAND):
            return
        controller = p.tags.get("CONTROLLER")
        if controller is None:
            ent = self._entities.get(p.entity_id, {})
            controller = ent.get("CONTROLLER")
        if controller is None:
            return
        new_friendly = int(controller)
        if new_friendly != self._friendly_player_id:
            self._friendly_player_id = new_friendly
            self._rebucket_from_entities()
        self._friendly_player_resolved = True

    def _rebucket_from_entities(self) -> None:
        """Re-attribute prior drawn/played rows using AUTHORITATIVE _entities CONTROLLER state.

        Replaces the old 'swap accumulated lists' approach (03-REVIEWS.md HIGH #2):
        the swap was correct only when ALL pre-resolution events were uniformly
        inverted. With mixed timing — some events before resolution (potentially
        wrong bucket using default _friendly_player_id=1), some after (correct
        bucket) — the swap would un-correct the post-resolution rows.

        This implementation walks each row, looks up the authoritative CONTROLLER
        from self._entities[row.entity_id], and places the row in the correct
        bucket based on the now-resolved _friendly_player_id. Rows whose entity
        is no longer in _entities (extremely rare) fall back to their own
        .controller attribute.
        """

        def _is_friendly(entity_id: int, fallback_controller: int) -> bool:
            ent = self._entities.get(entity_id, {})
            controller = ent.get("CONTROLLER", fallback_controller)
            return int(controller) == self._friendly_player_id

        all_drawn = list(self._player_drawn) + list(self._opponent_drawn)
        new_player_drawn: List = []
        new_opponent_drawn: List = []
        for row in all_drawn:
            if _is_friendly(row.entity_id, row.controller):
                new_player_drawn.append(row)
            else:
                new_opponent_drawn.append(row)
        self._player_drawn = new_player_drawn
        self._opponent_drawn = new_opponent_drawn

        all_played = list(self._player_played) + list(self._opponent_played)
        new_player_played: List = []
        new_opponent_played: List = []
        for row in all_played:
            if _is_friendly(row.entity_id, row.controller):
                new_player_played.append(row)
            else:
                new_opponent_played.append(row)
        self._player_played = new_player_played
        self._opponent_played = new_opponent_played

        self._refresh_state()
    ```
