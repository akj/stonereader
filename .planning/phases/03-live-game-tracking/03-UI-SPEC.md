# Phase 3 — UI Design Contract (Live Game Tracking)

> Visual + interaction contract for an accessibility-first wxPython desktop application. "UI" here covers BOTH the wxPython widget layout AND the speech/keyboard interaction contracts that are the primary user surface for screen-reader users on Windows.
>
> Generated by gsd-ui-researcher; verified by gsd-ui-checker.

---

## Scope Note (read first)

StoneReader is a Windows desktop app for blind/low-vision Hearthstone players using NVDA or JAWS. Visual styling tokens (colors, typography, spacing scales) are NOT load-bearing here — wxPython renders with the **OS native theme**, and the user's screen reader does not consume colors, fonts, or pixel offsets. Sections of the standard UI-SPEC template that don't apply (color palette, typography sizes, design tokens, shadcn registry) are marked **N/A — see rationale**.

The sections that ARE first-class for this phase:

1. **Speech announcement contracts** (per-zone phrasing, panel-entry phrasing, hotkey-triggered phrasing, interrupt vs queued semantics).
2. **Global hotkey contracts** (which `Ctrl+Shift+<letter>` chords, modifier semantics, conflict-failure UX).
3. **In-app keyboard contracts** (zone navigation key map, EVT_CHAR_HOOK routing, text-mode handling).
4. **Panel/widget contract** for `LiveGamePanel` (three-zone layout, label-before-control MSAA pattern, virtual `ListCtrl` with `AcceptsFocus() -> False`).
5. **Diminishing message UX rules** (already standardized via `ZoneNavigationMixin`).

These are specified deeply below.

## Layout Contract — `LiveGamePanel`

Vertical `wx.BoxSizer`. Top-down reading order matters for screen readers — items appear in the order NVDA's object navigation walks them.

```
+-----------------------------------------------------------+
| _TitleStaticText:  "Live Game — <matchup> — <deck name>"  |  <-- 1 row, label-style
+-----------------------------------------------------------+
| StaticText: "Remaining Deck:"                             |  <-- MSAA label
| _RemainingDeckListCtrl  (virtual, AcceptsFocus=False)     |  <-- list zone 1
+-----------------------------------------------------------+
| StaticText: "Opponent Hand:"                              |  <-- MSAA label
| _OpponentHandListCtrl  (virtual, AcceptsFocus=False)      |  <-- list zone 2
+-----------------------------------------------------------+
| StaticText: "Opponent Played:"                            |  <-- MSAA label
| _OpponentPlayedListCtrl (virtual, AcceptsFocus=False)     |  <-- list zone 3
+-----------------------------------------------------------+
```

**Title format (D-08, D-11):**

| Game state | Title text |
|------------|------------|
| No game seen this session | `"Live Game — No game in progress"` |
| Game in progress, deck detected | `"Live Game — Mage vs Warrior — Reno Quest Mage"` |
| Game in progress, no detection | `"Live Game — Mage vs Warrior — Unknown deck"` |
| Game ended (preserved per D-08) | `"Live Game — Mage vs Warrior (final) — Reno Quest Mage"` |

**MSAA label rule (semantic-HTML-equivalent):** Each `wx.StaticText` label sits **immediately before** its `wx.ListCtrl` in the BoxSizer. NVDA/JAWS infer the association by sibling order (no ARIA tags needed; wx has no ARIA layer). Same pattern as `views/card_browser.py:58-60`.

**Focus contract:** `LiveGamePanel` itself is the focus_target registered via `nav.register_panel("Live Game", panel, presenter, panel)`. The list ctrls return `AcceptsFocus() -> False` so Tab does not land on them; arrow keys are routed via the panel's `EVT_CHAR_HOOK` chain into the presenter's `get_key_map()` per the standard InputLayer pattern.

**View ↔ Presenter callback shape:**

```python
# Presenter exposes (public methods only — no private-attribute access from view):
presenter.set_on_state_changed(callback: Callable[[str, list, int], None])  # zone_name, items, cursor
presenter.set_on_title_changed(callback: Callable[[str], None])              # title text
```

The view's `_on_state_changed(zone_name, items, cursor)` calls `self._<zone>_list.set_items(items)` then `Select(cursor)` (Pitfall 3 mitigation). The view's `_on_title_changed(text)` calls `self._title.SetLabel(text)`.

> ⚠️ Reviewer concern (REVIEWS.md, Codex HIGH #3): All view-side reads of presenter state MUST go through public accessors. The view never reads `_zone_cursors`, `_current_state`, or `_format_title` directly.

## Speech Contract (PRIMARY USER SURFACE)

This section IS the design contract for screen-reader users. Every announcement that the presenter can produce is enumerated below with the exact format string, the trigger, and the interrupt semantics.

### Speech engine semantics

| Concept | Rule |
|---------|------|
| Default call | `self._speech.speak(text, interrupt=True)` |
| Interrupt-queued (rare) | `self._speech.speak_queued(text)` — used when chaining a follow-up announcement after a primary speak. Phase 3 v1 does NOT use queued speech. |
| Speech rule | Only presenters call `self._speech`. Views never call `SpeechService` directly (CLAUDE.md). |
| Silent during arrow-read | `_on_game_event` MUST NEVER call `self._speech.speak`. (D-07; REVIEWS.md confirms test lock at `test_silent_during_event`.) |
| Lifecycle silent | `GameStarted`/`GameEnded` events MUST NOT speak. (D-09; locked silent in v1.) |

### Per-zone row formats (driven by `_format_item_speech` override)

| Zone | Item type | Speech format | Source |
|------|-----------|---------------|--------|
| `remaining_deck` | `Tuple[Card, int]` | `"Reno Jackson, 1 copy, <pos> of <total>"` (singular) — `"Fireball, 2 copies, <pos> of <total>"` (plural) — `"Loatheb, 0 copies, <pos> of <total>"` (drawn-to-zero, only when detected deck known) | D-13 |
| `opponent_hand` | `OpponentHandRow(position, identity, drawn_turn, lineage)` | Three variants below | D-14 |
| `opponent_played` | `PlayedCard` | `"Turn 6, Reno Jackson, <pos> of <total>"` | D-15 |

**Opponent Hand row variants (D-14):**

| Condition | Speech |
|-----------|--------|
| `identity` known (revealed via SHOW_ENTITY) | `"Position 3, Reno Jackson, drawn turn 5, <pos> of <total>"` |
| `identity` unknown, `lineage` known | `"Position 3, unknown, generated by Wand of Disintegration turn 5, <pos> of <total>"` |
| `identity` unknown, `lineage` empty | `"Position 3, unknown, drawn turn 5, <pos> of <total>"` |
| `drawn_turn == -1` (unknown) | Speak `"drawn turn unknown"` instead of `"drawn turn -1"`. (REVIEWS.md, Codex MEDIUM #3 fallback wording.) |

### Zone-entry / hotkey-jump format (D-17)

When the user enters a zone (via `navigate_to_zone`, `jump_to_zone`, or a browse-open hotkey), the presenter announces:

```
"<Zone label>, <total> cards. <first row, full per-zone format with N of M suffix>."
```

| Zone | Zone label |
|------|------------|
| `remaining_deck` | `"Remaining deck zone"` |
| `opponent_hand` | `"Opponent hand zone"` |
| `opponent_played` | `"Opponent played zone"` |

**Examples:**

- `"Remaining deck zone, 18 cards. Glacial Shard, 1 copy, 1 of 18."`
- `"Opponent hand zone, 4 cards. Position 1, Reno Jackson, drawn turn 5, 1 of 4."`
- `"Opponent played zone, 6 cards. Turn 1, Frostbolt, 1 of 6."`

**Empty zone:**

- `"Remaining deck zone: empty"` (matches `ZoneNavigationMixin.navigate_to_zone` empty-list path at `presenters/base.py:68-70`).

**No game in progress (D-08):**

- `"No game in progress."` — spoken when `_current_state is None` and any zone is entered or any speak-only hotkey is invoked.

### Speak-only hotkey announcements (D-16)

These speak via `interrupt=True` and DO NOT change focus. Format is "tight one-sentence" so NVDA finishes before the next Hearthstone action.

| Trigger | Format | Source |
|---------|--------|--------|
| `Ctrl+Shift+D` (Deck Counts, LIVE-06) | `"<P> left, opponent <O>."` e.g. `"18 left, opponent 22."` — when no game: `"No game in progress."` | D-16 |
| `Ctrl+Shift+H` (Opponent Hand Count, LIVE-05) | `"Opponent has <N> cards."` — when no game: `"No game in progress."` (REVIEWS.md, Codex MEDIUM 03-06 #5: add presenter method `announce_opponent_hand_count()` so app wiring doesn't bypass presenter) | New (planner discretion per CONTEXT.md D-03) |

**Letter assignments locked here (Phase 3 v1):**

| Chord | Action | Type | Justification |
|-------|--------|------|---------------|
| `Ctrl+Shift+R` | Open Live Game panel, jump to Remaining Deck zone | browse-open | "R" mnemonic for "Remaining". No NVDA conflict (NVDA primary modifier is Insert/CapsLock, not Ctrl+Shift). |
| `Ctrl+Shift+O` | Open Live Game panel, jump to Opponent Hand zone | browse-open | "O" for "Opponent hand". |
| `Ctrl+Shift+D` | Speak deck counts (both players) | speak-only | "D" for "Deck count". |
| `Ctrl+Shift+H` | Speak opponent hand count | speak-only | "H" for "Hand count". |

**Avoided letters (intentionally not used):**

- `Ctrl+Shift+S` — common "save" shortcut in many Windows apps.
- `Ctrl+Shift+Q` — common "quit" shortcut.
- `Ctrl+Shift+P` — used by some IDEs / Spotify play-pause; high collision risk.
- `Ctrl+Shift+Esc` — system-reserved (Task Manager).
- `F12` and `Win+*` — system / debugger reserved.

**Modifier flag (locked, applies to all four chords):**

```python
MOD = wx.MOD_CONTROL | wx.MOD_SHIFT | 0x4000  # 0x4000 = MOD_NOREPEAT
```

`MOD_NOREPEAT` prevents OS-level key-repeat from firing the chord 30 times per second when held (Pitfall 5).

### Hotkey conflict / failure UX (Pitfall 4)

When `wx.Window.RegisterHotKey` returns `False` (chord already held by another app), `GlobalHotkeyService` accumulates the human-readable label in `self._failed`. After all four registrations attempted, the app announces ONCE at startup:

```
"Could not register hotkeys: Remaining Deck, Opponent Hand."
```

Format:
- Single failure: `"Could not register hotkey: <label>."`
- Multiple: `"Could not register hotkeys: <label1>, <label2>."`
- All four failed (worst case): announce + the panel is still reachable via Home menu → "Live Game".
- No failures: silent.

The announcement is queued (NOT interrupt) AFTER the StoneReader app's normal startup speech so it doesn't trample the home-screen first-item read.

### Speech ordering during browse-open (Pitfall 2)

When a browse-open hotkey fires:

1. `nav.show_panel("Live Game")` — shows the panel; schedules `wx.CallAfter(focus_target.SetFocus)`.
2. Same hotkey callback then calls `presenter.jump_to_zone("remaining_deck")` synchronously.
3. The zone-entry speech fires before focus arrives. **This is intentional and benign.** NVDA reads announced text without needing focus. Subsequent arrow keys land in the panel because focus has arrived by then.

A test (`test_browse_open_dispatch`) locks this contract.

### Speech during live updates (D-07 silence rule)

When Hearthstone emits a draw event mid-game and the user is arrowing in the Remaining Deck zone:

- `LiveGamePresenter._on_game_event(event, state)` updates `self._current_state`.
- `_notify_view()` re-renders the panel (passes new items + cursor index to view).
- The view re-selects the row at `cursor` (Pitfall 3 mitigation).
- **No `self._speech.speak(...)` call happens.** The user only hears speech on their next arrow key.

Test lock: `test_silent_during_event` asserts `speech.spoken == []` after firing a non-lifecycle event (per RESEARCH.md §"Validation Architecture" line 944).

### Diminishing message UX (carry-forward)

Inherited from `ZoneNavigationMixin.handle_inapplicable_zone` (`presenters/base.py:155-164`):

| Press count | Behavior |
|-------------|----------|
| 1st | Full help message |
| 2nd | Short message |
| 3rd+ | Silent |

Resets on zone change. Phase 3 reuses this pattern unchanged. Inapplicable-zone keys for Live Game are: pressing Enter on a list (no detail action), pressing letter keys in a list zone (no quick-jump for Phase 3 v1). Planner finalizes the exact help strings; default behavior is "do nothing silently after 2nd press."

## Keyboard Contract (in-panel)

In-panel keys route via `EVT_CHAR_HOOK` → `InputLayer._on_char_hook` → `presenter.get_key_map()`. Global hotkeys (`Ctrl+Shift+*`) DO NOT route through InputLayer — Windows delivers `WM_HOTKEY` directly to the frame via `EVT_HOTKEY`, a separate channel.

### `LiveGamePresenter.get_key_map()` (locked)

| Key | Action |
|-----|--------|
| `left` | `move_in_zone(-1)` — previous row in current zone |
| `right` | `move_in_zone(+1)` — next row in current zone |
| `up` | `read_detail_lines(item, direction=-1)` — previous detail line |
| `down` | `read_detail_lines(item, direction=+1)` — next detail line |
| `home` | `jump_to_first()` — first row in current zone |
| `end` | `jump_to_last()` — last row in current zone |
| `1` | `navigate_to_zone("remaining_deck", "Remaining deck zone")` — switch to zone 1 |
| `2` | `navigate_to_zone("opponent_hand", "Opponent hand zone")` — switch to zone 2 |
| `3` | `navigate_to_zone("opponent_played", "Opponent played zone")` — switch to zone 3 |

**Why number keys for zone switching:** The Live Game panel has three zones with no input fields, so number keys are unambiguous. `Tab` is reserved for OS-level focus walks (panel ↔ other panels). Number-key zone switching matches the "zone keys are always global — no enter/exit required" rule from CLAUDE.md.

**InputLayer interaction (carry-forward, no changes):**

- Text mode: not used by Live Game (no TextCtrls). Flag stays at default (False).
- Ctrl/Alt passthrough: a chord like `Ctrl+C` is allowed to pass through to wx default handling for clipboard copy (per `InputLayer._on_char_hook:84-86`). This means `Ctrl+Shift+R` would also try to passthrough — but global hotkeys are dispatched at the OS layer BEFORE EVT_CHAR_HOOK even fires when registered, so there's no conflict.
- Backspace / Escape: handled by `NavigationController` for "go back" — Phase 3 doesn't override these.

### Global hotkeys (out-of-app)

| Chord | Modifiers | VK | Action | Type |
|-------|-----------|----|----|------|
| `Ctrl+Shift+R` | `wx.MOD_CONTROL \| wx.MOD_SHIFT \| 0x4000` | `ord("R")` | Open panel + jump to Remaining Deck | browse-open |
| `Ctrl+Shift+O` | same | `ord("O")` | Open panel + jump to Opponent Hand | browse-open |
| `Ctrl+Shift+D` | same | `ord("D")` | Speak deck counts | speak-only |
| `Ctrl+Shift+H` | same | `ord("H")` | Speak opponent hand count | speak-only |

These four chords are the COMPLETE Phase 3 v1 hotkey lineup. Any future additions go through a separate phase.

### List row text (visual + screen-reader fallback)

The view's `OnGetItemText(item, column)` returns a one-line string per row. NVDA reads this when navigating object-style; the presenter's speech format is what the user hears for cursor-based navigation. Both should match closely for consistency.

| Zone | List row text |
|------|----------------|
| `remaining_deck` | `"<card.name> (<count>) — <card.cost> mana"` e.g. `"Reno Jackson (1) — 6 mana"` |
| `opponent_hand` | `"Pos <position>: <identity or '?'> — drawn turn <drawn_turn or '?'><lineage suffix>"` e.g. `"Pos 3: ? — drawn turn 5 (gen: Wand of Disintegration)"` |
| `opponent_played` | `"Turn <turn>: <card.name>"` e.g. `"Turn 6: Reno Jackson"` |

### Speech-only strings (already enumerated above — referenced here for completeness)

| Element | Copy |
|---------|------|
| Empty zone | `<Zone label>: empty` (e.g. `Remaining deck zone: empty`) |
| No game in progress | `No game in progress.` |
| Zone entry (full) | `<Zone label>, <total> cards. <first-row format>.` |
| Speak-only deck counts | `<P> left, opponent <O>.` |
| Speak-only opponent hand count | `Opponent has <N> cards.` |
| Hotkey conflict (one) | `Could not register hotkey: <label>.` |
| Hotkey conflict (many) | `Could not register hotkeys: <label1>, <label2>, ....` |

### Empty / loading / error states

| State | Copy |
|-------|------|
| Empty (any zone, in-game) | `<Zone label>: empty` |
| Empty (any zone, no game) | `No game in progress.` (panel-wide) |
| Detection running but deck not 30 cards yet | Title shows `Unknown deck` until detection completes; no special "loading" speech (D-09 silent on lifecycle). |
| Detection succeeded (one match) | Title updates to detected deck name; no speech (D-07/D-09). User notices on next zone entry. |
| Detection failed (0 or 2+ matches) | Title shows `Unknown deck`; no speech. |
| Hotkey conflict on launch | Spoken once at startup per "conflict / failure UX" above. |
| Game ended (post-game preserved per D-08) | Title appends `(final)`; zones still navigable; no speech. |
| Engine error (caught per `apply()` try/except) | Logged via `logger.exception(...)`; no speech (already covered by Phase 2 D-04). |

### Destructive actions

**None in Phase 3.** The Live Game panel is read-only — there are no buttons, no delete actions, no confirmations needed. (Phase 1 deck-deletion is unaffected.)

## Reviewer-Flagged UX Concerns (from 03-REVIEWS.md)

| Reviewer concern | Severity | How this contract addresses it |
|------------------|----------|-------------------------------|

Planner / requirements doc may need to mark LIVE-03 as "satisfied indirectly via D-13." |

| 30x copy deckstring not legal | MEDIUM | Test fixture concern, not contract concern — flagged for the planner to use a legal deck composition in detection tests. |
| Duplicated row-formatting (presenter speech vs view list text) | MEDIUM | Acknowledged: the visual list text and the spoken format are intentionally similar but not identical (visual can use punctuation like parentheses; spoken must read naturally). Both live in the view + presenter layers respectively. Planner may extract a `live_game_format.py` helper if duplication grows; not required for v1. |

## Acceptance Criteria for the UI Contract

A Phase 3 implementation satisfies this contract when:

- [ ] `LiveGamePanel` exists as `stonereader/views/live_game.py` with the three-zone vertical layout above and `style=wx.WANTS_CHARS`.
- [ ] All three `_*ListCtrl` widgets return `AcceptsFocus() -> False`.
- [ ] Each list ctrl has a preceding `wx.StaticText` MSAA label (`"Remaining Deck:"`, `"Opponent Hand:"`, `"Opponent Played:"`).
- [ ] Top of panel has a `_TitleStaticText` updated via `set_on_title_changed`.
- [ ] `LiveGamePresenter.get_key_map()` exposes the 9 keys above (left/right/up/down/home/end/1/2/3).
- [ ] `_on_game_event` never calls `self._speech.speak` (test lock: `test_silent_during_event`).
- [ ] Per-zone row format matches D-13/D-14/D-15 exactly (test locks: `test_remaining_deck_speech_format`, etc.).
- [ ] Zone-entry speech matches D-17 format (test lock: `test_zone_entry_format`).
- [ ] Speak-only `announce_deck_counts()` produces D-16 format (test lock: `test_announce_deck_counts`).
- [ ] Speak-only `announce_opponent_hand_count()` exists as a public presenter method (per REVIEWS.md fix).
